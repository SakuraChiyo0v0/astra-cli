# astra 部署手册（照着做）

> 写给**第一次接触这个项目的人或 AI**。按顺序执行，每步都有验证方法。
> 遇到"验证失败"就停下排查，不要跳过继续往下做。

## 你要部署的是什么

```
飞书用户  ⇄  飞书 App  ⇄  Hermes 容器（NAS 上）  ── shell ──▶  astra CLI
                                │                              │
                                ├─ 模型：workbuddy2api          ├─ 网易云 / B 站 / Steam
                                └─ 代理：mihomo:7890            └─ 下载到音乐/视频目录
```

**astra** 是一个命令行工具，把"下载网易云歌曲、B 站视频、查 Steam 愿望单"这些事做成一条命令。
它不自带界面，是给 AI（这里的 Hermes）调用的。

**Hermes** 是一个 AI agent，接飞书。你在飞书里说"下载周杰伦的晴天"，它理解后调用 `astra` 执行。

最终用户看到的是：**在飞书里跟机器人说话**。

---

## 第 0 步：先搞清楚三个前提

动手前确认这三件事，缺一个都做不下去：

| 前提 | 怎么确认 | 没有怎么办 |
|-|-|-|
| NAS 上能跑 Docker | `docker ps` 有输出 | 这台机器不适合 |
| 有一个飞书企业自建应用 | 有 App ID 和 App Secret | 见第 4 步创建 |
| 有一个 OpenAI 兼容的模型接口 | 有 base_url 和 api_key | 本机常配 workbuddy2api，或其他 |

---

## 第 1 步：准备目录

选一个部署根目录，下面按这个结构放东西。**下面用 `/volume1/docker` 举例**，
不同机器路径不同，替换成自己的。

```bash
export DEPLOY_ROOT=/volume1/docker

mkdir -p $DEPLOY_ROOT/astra/bin
mkdir -p $DEPLOY_ROOT/astra/home
mkdir -p $DEPLOY_ROOT/astra/skills
mkdir -p $DEPLOY_ROOT/hermes/data
mkdir -p "$DEPLOY_ROOT/../音乐/astra"     # 音乐下载目标，按实际音乐目录改
```

最终长这样：

```
$DEPLOY_ROOT/
├── astra/
│   ├── bin/astra.mjs          ← CLI 单文件（第 2 步）
│   ├── bin/astra              ← 包装脚本（第 2 步）
│   ├── home/                  ← astra 的状态：配置、曲库、音源脚本
│   └── skills/                ← 给 Hermes 的技能说明
│       ├── music/SKILL.md
│       ├── bili/SKILL.md
│       └── vrchat/SKILL.md
└── hermes/
    ├── docker-compose.yml     ← 第 5 步
    ├── Dockerfile             ← 第 5 步
    ├── .env                   ← compose 变量（第 5 步）
    └── data/                  ← Hermes 的 /opt/data
        ├── .env               ← 密钥（第 4 步）
        └── config.yaml        ← 模型与工具配置（第 5 步）
```

## 第 2 步：放 astra 的可执行文件

astra 打包后是**一个文件**，不需要 `node_modules`。

```bash
# 从仓库拿 dist/astra.mjs（构建方式：npm ci && npm run build）
cp /path/to/astra.mjs $DEPLOY_ROOT/astra/bin/astra.mjs
chmod 755 $DEPLOY_ROOT/astra/bin/astra.mjs

# 包装脚本，让 `astra` 这个命令可用
cat > $DEPLOY_ROOT/astra/bin/astra <<'EOF'
#!/bin/sh
exec node /opt/astra/bin/astra.mjs "$@"
EOF
chmod 755 $DEPLOY_ROOT/astra/bin/astra
```

**为什么两行都要 `chmod 755`**：通过 WebDAV/SMB 传上来的文件经常是 000 或 600 权限，
容器里读不到。这是最常见的"装好了但跑不起来"的原因。

验证（需要一个有 Node 的环境，容器还没起就先跳过）：

```bash
node $DEPLOY_ROOT/astra/bin/astra.mjs version
# 期望：{"ok":true,"data":{"version":"x.y.z","node":"v24..."}}
```

## 第 3 步：放技能说明（SKILL.md）

Hermes 靠这些文件知道"什么时候该用 astra、怎么用"。

```bash
cp -r /path/to/astra-cli/skills/* $DEPLOY_ROOT/astra/skills/
ls $DEPLOY_ROOT/astra/skills/
# 期望看到：bili  music  vrchat
```

每个子目录里有一个 `SKILL.md`。这些文件是给 AI 读的说明书，你可以按需要修改。

## 第 4 步：创建飞书应用并拿密钥

如果已经有应用，跳到"填密钥"。

### 4.1 建应用

1. 打开 https://open.feishu.cn/ → 开发者后台 → 创建企业自建应用
2. **添加应用能力 → 机器人**
3. **权限管理**，加这几个：

   | 权限 | 用途 |
   |---|---|
   | `im:message` | 收消息 |
   | `im:message:send_as_bot` | 发消息 |
   | `im:resource` | 收图片/文件 |
   | `im:chat` | 读群信息 |
   | `im:chat:readonly` | 读群列表 |

4. **事件与回调**
   - 连接方式选 **长连接（WebSocket）** ← 重要，这样不需要公网 IP
   - 事件订阅：`im.message.receive_v1`
   - 回调配置：`card.action.trigger`
5. **版本管理 → 创建版本 → 发布**（不发布权限不生效）

### 4.2 填密钥

```bash
cat > $DEPLOY_ROOT/hermes/data/.env <<'EOF'
# 模型（换成你自己的）
OPENAI_BASE_URL=http://workbuddy2api:7863/v1
OPENAI_API_KEY=你的模型key

# 飞书
FEISHU_APP_ID=cli_xxxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxx
FEISHU_DOMAIN=feishu
FEISHU_CONNECTION_MODE=websocket

# 只允许这个人用机器人（填自己的 open_id，ou_ 开头）
# 不知道 open_id 就先留空，启动后从日志里找（第 7 步）
FEISHU_ALLOWED_USERS=
EOF
chmod 600 $DEPLOY_ROOT/hermes/data/.env
```

**`FEISHU_ALLOWED_USERS` 留空的后果**：任何人只要找到这个机器人都能用它。
部署完尽快填上。

## 第 5 步：写 Hermes 的 compose 和配置

### 5.1 Dockerfile

官方镜像**不允许运行时装依赖**，而飞书 SDK（`lark-oapi`）不在镜像里。所以要派生一个镜像。

```bash
cat > $DEPLOY_ROOT/hermes/Dockerfile <<'EOF'
FROM nousresearch/hermes-agent:latest

# 官方镜像的 venv 里没有 pip，用镜像自带的 uv 装。版本对齐 hermes 的 pyproject。
RUN UV=$(ls -d /opt/hermes/tools/uv-*/uv | head -1) && \
    "$UV" pip install --python /opt/hermes/.venv/bin/python --no-cache \
      "lark-oapi==1.6.8" "qrcode==7.4.2" && \
    /opt/hermes/.venv/bin/python -c "import lark_oapi, qrcode; print('feishu deps ok')"
EOF
```

> 构建时如果报 `No module named pip`，说明用了 `python -m pip`，按上面用 uv。

### 5.2 compose 变量

```bash
cat > $DEPLOY_ROOT/hermes/.env <<'EOF'
DEPLOY_ROOT=/volume1/docker
MUSIC_DIR=/volume1/音乐/astra
HERMES_UID=1000
HERMES_GID=10
HERMES_TAG=latest
HERMES_DASHBOARD=1
EOF
```

- `HERMES_UID/GID`：容器内 hermes 用户的身份，要对 `data`、`astra/home`、音乐目录有写权限。
  用 `ls -n` 看这些目录的属主，填对。
- `MUSIC_DIR`：音乐下载目标。单独用 `astra/` 子目录，别和别的工具混。

### 5.3 docker-compose.yml

```bash
cp /path/to/astra-cli/deploy/hermes/docker-compose.yml $DEPLOY_ROOT/hermes/
```

**这个文件里有四处按你的环境可能要改**：

| 地方 | 说明 |
|-|-|
| `workbuddy2api_default` | 模型服务所在的 docker 网络。用别的模型就换成对应的网络，或删掉这一行 |
| `proxy-net` | 出站代理网络（第 6 步）。**不用代理就删掉这一行和文件末尾的声明** |
| `/home`、`/volume1` 两个挂载 | 给 agent 访问宿主文件。**不放心就删掉**，只留 astra 需要的目录 |
| `/var/run/docker.sock` 和 `group_add: 121` | 让 agent 能操作 Docker。**等于给它宿主机 root**，不放心就删掉 |

`group_add` 的 121 是 NAS 上 `docker.sock` 的属组，用 `ls -n /var/run/docker.sock` 确认。

### 5.4 config.yaml

```bash
cp /path/to/astra-cli/deploy/hermes/config.yaml $DEPLOY_ROOT/hermes/data/
```

里面有模型和工具配置。**关键几项**：

```yaml
model:
  provider: "custom"
  base_url: "http://workbuddy2api:7863/v1"   # 换成你的
  default: "cn:deepseek-v4-pro"              # 换成你要的模型

terminal:
  env_passthrough: [ASTRA_HOME, ASTRA_MUSIC_DIR]   # 必须，否则 astra 找不到数据目录

skills:
  external_dirs: [/opt/astra/skills]               # 指向第 3 步的目录

security:
  allow_lazy_installs: true                        # 允许装依赖
```

## 第 6 步（可选）：出站代理

**什么时候需要**：要访问国内直连不通的域名。实测 Steam 的 `store.steampowered.com`
和 `steamcommunity.com` 在 NAS 上直连超时，必须走代理。B 站、网易云不需要。

### 6.1 建独立网络

```bash
docker network create --driver bridge --label purpose=outbound-proxy proxy-net
```

**必须是独立网络**，不要借用别的项目的网络（比如某个 compose 自动创建的 `xxx_default`）。
借用的话，那个项目一 `docker compose down`，代理就跟着断，而这个依赖藏在
`external: true` 里，出问题时很难发现。

### 6.2 让代理容器接入

在**代理容器的 compose** 里加：

```yaml
services:
  mihomo:
    networks:
      - proxy-net

networks:
  proxy-net:
    external: true
    name: proxy-net
```

然后 `docker compose up -d` 重建。

### 6.3 验证

```bash
# 从 Hermes 容器里能解析到代理
docker exec hermes getent hosts mihomo
# 期望：172.x.x.x  mihomo
```

### 6.4 astra 侧配置（第 7 步之后做）

```bash
docker exec hermes sh -c "
  astra config set proxy.url http://mihomo:7890
  astra config set proxy.include steampowered.com,steamcommunity.com
  astra config set proxy.exclude bilibili.com,music.163.com
"
```

`include` 是走代理的域名，`exclude` 是不走的（优先级更高）。
**别让 B 站、网易云走代理** —— 多绕一跳更慢，而且 B 站对代理 IP 更敏感。

## 第 7 步：启动

```bash
cd $DEPLOY_ROOT/hermes
docker compose build          # 第一次要构建，约 1-2 分钟
docker compose up -d
docker compose logs -f --tail 50
```

**看日志里这几行，缺哪个就说明哪里没准备好**：

| 期望看到 | 说明 |
|-|-|
| `feishu deps ok` | 第 5.1 步的镜像构建成功 |
| `[Lark] ... connected to wss://msg-frontier.feishu.cn` | 飞书连上了 |
| `gateway is now running under s6 supervision` | 网关起来了 |
| `HERMES_DASHBOARD_READY port=9119` | 面板起来了 |

如果看到 `Platform 'feishu' ... requirements not met` 或
`Platform 'feishu' is registered but adapter creation failed`，说明 lark-oapi 没装上，
回去检查 5.1 的 Dockerfile 有没有真的构建。

## 第 8 步：验证 astra 能用

```bash
# 1. 命令在 PATH 里
docker exec hermes astra version

# 2. 自检
docker exec hermes astra doctor
```

`doctor` 会输出一堆检查项，分三类：

- `required` 失败 → **必须修**，不然后面都做不了
- `domain` 失败 → 对应能力不可用，其它还能用
- `optional` 失败 → 只是少了点便利

每条失败的检查都带 `hint`，照着做。

### 8.1 导入音源脚本（网易云下载必需）

astra 靠"洛雪音源脚本"拿播放地址。脚本要你自己提供（常见的是 `qdy.js` 之类）。

```bash
# 先把脚本放进容器能读到的地方，比如：
docker cp ./qdy.js hermes:/opt/astra/home/import/qdy.js

# 导入（会先试加载，加载不起来会报错）
docker exec hermes astra music source add /opt/astra/home/import/qdy.js --id qdy

# 确认
docker exec hermes astra music source list
```

没有音源也能用：登录网易云账号后走官方通道，但音质可能低。

### 8.2 测试下载

```bash
docker exec hermes astra music get 光年之外 邓紫棋
```

期望返回 `{"ok":true,"data":{"status":"downloaded","path":"/music/..."}}`。
文件会出现在 `MUSIC_DIR` 下。

## 第 9 步：接飞书白名单

**这步不做，谁都能用你的机器人。**

1. 在飞书里找到这个机器人，发一条消息（比如"你好"）
2. 看日志找你的 open_id：

```bash
docker exec hermes sh -c "grep -o 'ou_[a-z0-9]*' /opt/data/logs/gateways/default/current | sort -u"
```

3. 填进 `$DEPLOY_ROOT/hermes/data/.env` 的 `FEISHU_ALLOWED_USERS=ou_xxxx`
4. `docker compose restart`

5. 再发一条消息，这次应该能收到回复了。

## 第 10 步：更新到新版本（部署已存在时）

上面九步只管第一次装。**仓库发新版不会自动更新 NAS** —— 版本号是打包时写死进
`astra.mjs` 的（`scripts/build.mjs` 里 `define: ASTRA_VERSION`），文件不换，版本号就不变。

### 10.1 先确认要更新

```bash
# NAS 上现在跑的是哪个版本
docker exec hermes astra version
```

对照仓库的最新 tag / CHANGELOG，一样就不用动。

### 10.2 换上新的产物

在**开发机**上构建（版本号取自 `package.json`，要发版先改它）：

```bash
npm ci && npm run build
node dist/astra.mjs version    # 先本地确认版本号是对的
```

把 `dist/astra.mjs` 传到 NAS 的 `$DEPLOY_ROOT/astra/bin/astra.mjs`，覆盖旧的。

**传完立刻修权限。** 通过 WebDAV/SMB 上传的文件经常是 000，容器读不到 ——
表现是 `astra` 突然 `command not found` 或 `Permission denied`：

```bash
chmod 755 $DEPLOY_ROOT/astra/bin/astra.mjs
```

### 10.3 生效

`bin/astra.mjs` 是**只读挂载**（`${DEPLOY_ROOT}/astra/bin:ro`），每次 `docker exec`
都从宿主读文件，所以**不用重建容器**，下次调用就是新版本：

```bash
docker exec hermes astra version    # 期望看到新版本号
```

### 10.4 skill 文档也变了的话

```bash
cp -r /path/to/astra-cli/skills/* $DEPLOY_ROOT/astra/skills/
chmod -R 755 $DEPLOY_ROOT/astra/skills
```

`skills` 是可写挂载（Hermes 自己也会改它），同样不用重启。
**但 Hermes 可能在启动时读了 skill 列表**，改完如果新技能不出现，`docker restart hermes`。

### 10.5 什么时候必须重启

| 改了什么 | 要重启吗 |
|-|-|
| `astra.mjs`（CLI 代码 / 版本） | 不用 |
| `skills/` 下的 SKILL.md | 一般不用，技能列表没更新才重启 |
| `astra/home/` 里的配置、曲库 | 不用 |
| `data/.env`、`data/config.yaml` | **要**（`docker compose restart`） |
| `docker-compose.yml`、`Dockerfile` | **要重建**（`docker compose up -d`） |

重启会中断正在跑的后台任务（飞书里会看到 shutting down，属正常）。
有 `astra music job <id>` 在跑的话，等它结束再重启。

### 10.6 更新后验证

```bash
docker exec hermes astra version
docker exec hermes astra doctor
```

`doctor` 的 `required` 项要全绿。改了域相关的东西，再跑一次真实下载确认真能落地。

## 常见问题

### `astra: command not found`

`astra` 包装脚本没挂进容器，或者挂载点的权限不对。
检查 compose 里这行：`${DEPLOY_ROOT}/astra/bin/astra:/opt/data/.local/bin/astra:ro`，
以及宿主上 `ls -l $DEPLOY_ROOT/astra/bin/astra` 是不是 `-rwxr-xr-x`。

### 下载报权限错误

`ls -n $MUSIC_DIR` 看属主，`HERMES_UID/GID` 要能写这个目录。

### 飞书连不上

- `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 填错
- 应用没发布（权限不生效）
- 连接方式没选**长连接**

日志里会有具体的错误码。

### 代理不通

```bash
# 从容器里测
docker exec hermes astra steam doctor
```

`store_api` 失败通常是没配代理或代理没接进 `proxy-net`。

### 端口冲突

compose 里映射了 `9119:9119`（Web 面板）。宿主上这个端口被占用就换一个，
或者删掉 `ports` 那两行（面板只是可选的）。

- [ ] 能下载一首歌，文件出现在 `MUSIC_DIR`
- [ ] 不需要代理的话，compose 里 `proxy-net` 相关的行已删除
- [ ] `docker exec hermes astra version` 的版本号与仓库最新 tag 一致（见第 10 步）
