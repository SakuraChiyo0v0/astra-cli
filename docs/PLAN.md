这几条不加平台、不加功能，但直接决定"部署之后能不能安稳跑"。

| # | 项 | 说明 | 验收 | 估时 |
|-|-|-|-|-|
| P0-1 | ✅ `doctor` 查目录可写（v0.9.0 由另一会话完成，已验证：只读目录能被发现） | 现在只查网络和会话。NAS 上因为 WebDAV 上传的文件是 000 权限踩过一次，当时是下载失败才发现 | 故意把音乐目录设成只读，`doctor` 要能报出来 | 2h |

| P0-3 | ✅ 凭据统一管理（两域→三域 + `login clear`） | 网易云 / B 站 / VRChat 各存一个 JSON，过期提示、清理方式都不一致 | `astra login` 能统一看状态（已有）+ 统一清理；坏文件能识别 | 3h |
| P0-4 | ✅ 磁盘用量检查（进 doctor，低于 10GB 告警） | 音乐 + 视频目录会持续增长，没有告警 | 进 `doctor`，超阈值在结果里标出来 | 2h |
| P0-5 | ⬜ CI | 三个 session 并行改同一仓库，冲突只能事后发现 | 推 GitHub 后自动跑 `npm run check` | 4h |

## 八、已完成（不用再看）

- info / audio / cut / transcode / thumbnail / concat / watermark

**VRChat**（33 命令）

- 头像（列表/切换/回退）、收藏（列表/增删/分组管理）、经济（余额/交易明细）、系统信息
- 写操作统一走预览 + 一次性令牌确认

**基础设施**
- 统一 JSON 输出与退出码、配置、飞书通知
- `core/confirm.ts` 写操作二次确认（跨域共用）
