# 2026-10-23 内嵌歌词改同步格式

## 现象

`music.lyric = both` 时，落盘的 `.lrc` / `.word.lrc` 都带时间戳，但**写进文件内嵌的
`LYRICS` 是剥掉时间戳的纯文本**，Navidrome 解析不出滚动歌词，直接显示"无歌词"。

## 根因有两个，不是一个

### 1. 内嵌用的是 `lyricBody.text`，不是 `lyricBody.lrc`

`lyricText()` 的职责就是把时间戳剥干净（用于纯文本场景）。内嵌直接拿了它。

### 2. 逐字歌词在写标签**之后**才取，内嵌根本拿不到

原顺序：

```
取网易云歌词 → 取封面 → 组装 tags → 写标签 → rename → 写 .lrc → 取酷狗逐字 → 写 .word.lrc
                                                          ↑ 内嵌早就写完了
```

所以就算第 1 点改了，内嵌也只能拿到普通 LRC，拿不到逐字。

**修法**：把逐字歌词的获取提到写标签之前，取一次、两处复用（内嵌 + `.word.lrc`）。
这样还顺带省了一次网络请求。

## 取值设计

| `music.lyric` | 内嵌 | 落 `.lrc` | 落 `.word.lrc` |
|-|-|-|-|
| `embed`（默认） | 逐字 `<>` → LRC `[]` → 纯文本 | 否 | 是 |
| `embed-synced` | 同上 | 否 | 是 |
| `embed-plain` | 纯文本 | 否 | 是 |
| `both` | 逐字 `<>` → LRC `[]` | 是 | 是 |
| `lrc` | 否 | 是 | 是 |
| `none` | 否 | 否 | 否 |

`embed` 与 `embed-synced` 行为一致 —— 保留两个名字是因为需求里提了 `embed-synced`，
而 `embed` 已经有一堆配置在用，改语义会坑到存量部署。

`embed-plain` 是给不认时间戳的老播放器留的退路。默认不带时间戳反而更符合"内嵌就该能滚动"的直觉。

## 踩过的坑

**1. 验证脚本自己写错，误判成"写入失败"。**

第一次验证从 VORBIS_COMMENT 里读歌词，用了：

```ts
const text = block.data.toString('utf8')
const line = text.split('\n').find((l) => l.startsWith('LYRICS='))
```

**Vorbis comment 是「4 字节小端长度 + 内容」的序列**，长度前缀里含 `0x00` 字节，
`toString` 之后这些字节变成乱码穿插在文本里，`split('\n')` 切出来的行根本对不上。
→ 必须按长度前缀逐条解析。改对之后 `LYRICS=[00:00.03]<00:00.03>YOASOBI...` 正常读出来了。

**以为自己写坏了，实际是读法错了。** 这一轮浪费在验证脚本上的时间比改代码还多。

**2. ffprobe 的标签前缀是 `TAG:`，不是裸的 `KEY=`。**

用 `<KEY>=` 去匹配 `<KEY>=` 拿到的全是空串。而且：

- FLAC 的歌词在 `TAG:LYRICS=`
- MP3 的歌词在 **`TAG:lyrics-und=`** —— USLT 帧带语言码 `und`，ffprobe 会把它拼进标签名

两次都误判成"读不到"，实际数据一直都在。

**3. 音频字节没被改动 —— 这条专门写了测试，不是随口说的。**

写歌词会重建 ID3 / VORBIS_COMMENT 块，体积会变。
测试对写前写后的 `audioPayload()` 取 sha256 比对，确认音频帧一字节没动。

## 验证

```
embed         首行: "[00:00.03]<00:00.03>YOASOBI <00:"   带时间戳 ✅
embed-synced  同上                                        ✅
both          同上                                        ✅
embed-plain   首行: ""                                    不带（预期）

MP3  ffprobe: TAG:lyrics-und=[00:12.34]<00:12.34>hello world   ✅
FLAC ffprobe: TAG:LYRICS=[00:12.34]<00:12.34>hello world       ✅
```

测试变红验证：把 `pickEmbeddedLyrics` 改回总是返回 `plain`，5 条测试立刻红。

## 顺带修的

**`music.subscribe` 的音质写死 `flac`。** 代码是 `sub.quality ?? 'flac'`，
用户把 `music.quality` 改成 320k 省流量，订阅仍然按 flac 下 —— 配置没生效。
改为 `?? getConfig('music.quality')`。

## 新增 `astra music template`

模板变量原先只挤在 `config list` 的一行描述里，`{albumartist}` 在合辑（`Various Artists`）
和合作曲（主歌手）上的取值差异完全说不清。新命令列出全部变量 + 取值示例，支持 `--set`。

## 没做

- 没有回填已下载文件的歌词标签。存量文件要重新内嵌得重下或另写 retag 命令。
- SYLT（同步歌词帧）没有实现。实测 Navidrome 读的是 LRC 文本格式，不需要 SYLT。
