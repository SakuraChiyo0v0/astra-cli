# 2026-11-09 comic 后台任务与订阅

## 做了什么

给 `astra comic` 补上和 bili / music 同级的能力（v0.32.0）：

- `comic get` 多话本默认开后台任务，`comic job / jobs / job cancel / job resume`
- `comic subscribe add / list / set / remove / run`，cron 调 `subscribe run`
- `comic search` 输出 `exact / ambiguous / empty`
- 下载结果报 `registered`，让"没进资产库"看得见

## 关键取舍

| 点 | 决定 | 原因 |
|-|-|-|
| 任务机制 | 复用 `core/jobs.ts`，注册 `comic` 域处理器 | 已有通用骨架（建任务、分离 worker、取消、恢复、通知）；`astra jobs` 自动能列 |
| 任务项粒度 | 一项 = 一话 | 一话内图片已并发；话做项，失败可按话重试，订阅也按话记账 |
| 话间并发 | 1 | 一话内默认 3 并发；再叠话间并发对上游连接数太多 |
| 默认后台 | 多话本默认后台，单话 / `--chapter` 当场 | 一本几十话同步跑会超出 Hermes 的单次调用耐心；单话十几秒，当场返回更好用 |
| 订阅存储 | 复用 `subscriptions` 表，kind = `comic-album`；`last_seen` 存基线、`seen_pages` 存 `{章节id: 话数}` | 和 bili 一样不另建表、不加迁移 |
| 基线 | 默认把现有话记为基线，`--backfill` 不记 | 和 bili / music 一致：订阅只管"之后出的"；补旧话交给 `comic get` |
| 记账时机 | `afterFinish` 里只记 downloaded / skipped | bili 那边踩过：失败的提前记了就永远补不上 |
| 目录命名 | 不新增，沿用 `comic.template` | 和 `comic get` 一致 |
| 检查频率 | `--every` 默认 24h，建议 cron 每 6 小时调 `subscribe run` | 和 bili 订阅一致 |

## 踩过的坑

- **以为订阅表是各域隔离的，实测 `music subscribe list` 会列出所有行。**
  `src/music/subscribe.ts` 的 `listSubscriptions` 是 `select * from subscriptions`，
  没有按 kind 过滤；bili 订阅从 0.1x 起就混在里面，`music subscribe run --all`
  会拿 `bili-season` 去当歌单查。之前没暴露，大概是 NAS 上没人同时开两种订阅。
  加漫画订阅前先修了（只认 playlist / album / artist），测试退回修复会红。
- **以为 `lib adopt` 要改才能认漫画，实测 0.31.0 已经认 `.astra-comic.json`。**
  真缺口在另一头：`mirrorFile` 在漫画目录不是 lib root 时**静默返回 false**，
  下载结果看不出"一页都没登记"。实测临时目录下完 `资产库登记 0/8 页`。
  这次让 `downloadChapter` 数 `registered`，并在 get 结果里给 warning。
- `lib root add` 在新 `ASTRA_HOME` 下报 `资产库还没初始化（缺 4 个迁移）`，要先 `astra db migrate`。
  NAS 上早已迁过，不影响；本地验证时记得先跑。
- Python 改文件在 Windows 上默认写 CRLF，`git diff` 报整文件改动。改完统一转回 LF。

## 验证

- `npm run check`：typecheck、build 通过；测试 510 个里 498 pass / 10 fail / 2 skip。
  10 个失败（lib-scan / lib-find / db-migrate-concurrent / steam 状态文件权限等）
  **在改动前的 base 上同样失败**（497 个里 10 fail），是 Windows 本机环境问题，不是这次引入的
- 新增 13 个测试：`tests/comic-jobs.test.ts`（worker 本进程跑、假 client）、
  `tests/comic-search-decision.test.ts`（2026-10-30 抓的真实搜索结果夹具）。
  退回两处修复（music kind 过滤、只记成功的话）时对应测试变红
- 真站端到端（临时目录，一本 8 页单话）：`get --background` → `job --wait` 得 done；
  `db migrate` + `lib root add` + `lib adopt` 认领 8 页；再 `get --wait` 为 already_have 且 `registered: 8`；
  `subscribe add` → `run` 得"没有新话"，第二次 `run` 不到点。**没验**：真有新话时的订阅补下（需要一本正在更新的连载）
