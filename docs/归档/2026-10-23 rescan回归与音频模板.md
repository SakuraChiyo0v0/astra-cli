# 2026-10-23 清单 v0.12.16 复测三条

`--rescan-pages` 在 0.12.16 造成了**比原 bug 更危险**的回归：触发全量重下。

## 1c：我的修复引入了新问题

0.12.16 我把"记录缺失"改成"一页都没下过"，这在语义上是对的
（空数组不可能表示"下过了"）。但我**保留了 `--rescan-pages` 的清空语义**：

```ts
if (patch.resetPages === true) sets.push("seen_pages = '{}'")
```

清空 + "无记录=没下过" = 201 个视频全部重下。实测跑了 209 项、311MB 才被取消。

**这是我上一轮留下的隐患**：0.12.16 改判据时没回头检查"谁在清空记录"。

### 换了两版判据才定下来

**第一版：磁盘核对**。按当前模板算出每个分 P 该在哪个路径，`existsSync` 判断。

写完在本地跑，发现路径对不上：

```
预测: 视频/东洋雪莲/⚡《鳄鱼摇の小曲》🐊…⚡/01 _.mp4
实际: 视频/Bilibili/东洋雪莲/《鳄鱼摇の小曲》《绿色DJ》完整版…​.mp4
```

两个原因叠加：
- `bili.template` 从 `{uploader}/{title}/…` 改成了 `Bilibili/{uploader}/…`
- 单 P 视频渲染出来没有 `01 ` 前缀（part 为空）

**路径取决于下载当时的模板**。模板改过一次，老文件就都算不出来。
按磁盘核对的结果是"全都没下过" → 又变回全量重下，只是换了个形状。

**第二版（最终）：历史下载记录**。查 `job_items` 里 status 为
`downloaded` / `skipped` 的项，从 meta 里取 `bvid` + `pageIndex`。

这个判据与模板无关、与后来有没有改配置无关，只反映"确实下成功过什么"。

明确它的局限：**手删的文件它不知道**。所以它不能答"磁盘上现在有什么"，
但能答"别重下已经下过的" —— 后者才是这个开关要的。

### 一个中途发现的 bug

第一版磁盘探测里，我拼的 `VideoInfo` 缺 `owner` 字段：

```
TypeError: Cannot read properties of undefined (reading 'name')
    at targetPathFor (download.ts:162)
```

而外面套着 `catch { return false }` —— **崩溃被吞成"没下过"，于是重下**。
这类"错误路径退化成最坏行为"的写法要小心：宁可让它抛，也不要静默走错分支。

## 2b：B 站音频专用模板

`music.template` 会把视频标题当专辑名，于是一个视频一个目录。订阅一开就是 201 个子目录。

新增 `bili.audio-template`，留空则退回 `music.template`（向后兼容）。

变量沿用 `bili.template` 那套（`{uploader} {title} {page} {bvid} …`），
同时也提供音乐模板那套（`{artist} {album} …`），两种写法都能用。

## 2c：TIT2 取错了字段

```
分 P 名:  绿色
视频标题: ⚡《鳄鱼摇の小曲》🐊《绿色DJ》完整版…⚡
TIT2:    绿色        ← 错，应该是 绿色DJ
```

`《…》` 取**最后一个**：前面常是副标题或系列名（这个例子里
《鳄鱼摇の小曲》是小曲名，《绿色DJ》才是歌名）。

没有《》时退回分 P 名，再没有才用视频标题。
