# 2026-10-23 合辑与专辑艺术家

## 起因

Navidrome 里群星合辑被拆得七零八落。需求原文提了四条：album_artist 缺失时取首位歌手、
标签保持多值、新增 `{primary_artist}`、合辑归到 `合辑/`。

## 先纠了三处与需求不符的事实

动手前对着代码和接口核了一遍，有三条前提是错的。**其中两条如果照着做，会改坏本来对的东西。**

### 一、album_artist 早就是"第一位歌手"了，不是拼接全部

需求说"专辑艺术家缺失时，astra 用全部歌手拼接回退"。实际 `download.ts` 里是：

```ts
const albumArtists = album?.artists.length ? album.artists : track.artists.slice(0, 1)
```

重试一眼看着像，但它 `slice(0, 1)` —— 已经是取第一位。
拼全部歌手的是 **`{artist}` 模板变量**（`track.artists.join(', ')`）。
→ 所以真正要做的是给模板加一个 `{primary_artist}`，而不是去"修" albumArtists。
照着需求改会把正确的回退逻辑改错。

### 二、网易云里 Various Artists 叫「群星」

实测 `/api/v1/album/388647552`（那些年的华语情歌）：

```json
album.artists: [{"id":122455,"name":"群星","alias":["华语群星"]}]
songs[0]: 雪中莲  ar: ["王菲"]
songs[1]: 断点    ar: ["张敬轩"]
```

按需求写的 `album_artist == "Various Artists"` 去匹配，**永远匹配不上**。
"Various Artists" 只是我们要写进标签的规范名，不是接口里的值。

### 三、合辑只能看专辑级 artist，不能看曲目

上面那份数据里，每首歌的 `ar` 只有它自己的歌手。想靠"曲目歌手互不相同"来判合辑，
会得出"这不是合辑"—— 因为这个判断在每首歌上都成立，包括单曲。

## 做了什么

- 新增 `src/music/album-artist.ts`：`isCompilation` / `albumArtistsFor` / `primaryArtist`，全是纯函数。
  单独成文件是为了测试能直接 import —— `download.ts` 一被 import 就拉进网络、音源脚本、ffmpeg。
- 合辑判定只认显式标记：`群星`（及 Various Artists / VA / V.A. 这些其它平台的写法），
  外加网易云群星 id `122455` 兜底（名字将来改了 id 不会变）。
- 合辑的 `album_artist` 标签写 `Various Artists`。
- 新增配置 `music.compilation-dir`（默认 `合辑`）。合辑的落盘模板换成
  `<合辑目录>/{album}/<原模板的文件名段>`，目录前缀**不**用用户模板的。
- 模板变量新增 `{primary_artist}`。

## 踩过的坑

**1. 一开始打算按"专辑歌手有多个"来判合辑，这会把合作专辑误伤。**

两个人各出一半的专辑，专辑级 artist 就是两个歌手。按"多于一个就是合辑"判，
整张专辑会被扔进 `合辑/`，而且**不会报错、不会有人立刻发现**——要等用户翻目录看到。
→ 只认显式的群星标记。判不准时宁可按普通专辑走。留了测试 `合作专辑不算合辑` 钉住这条。

**2. 合辑的目录前缀不能用用户模板。**

第一版是拼一个 `{compilation-dir}/{album}/{track} {title}.{ext}` 固定模板，
但这等于把用户的文件名命名习惯也一起改掉了。改成"取用户模板的最后一段做文件名，前面换成合辑目录"。
危险点在**用户模板可能是平铺的**（`{artist} - {title}.{ext}`，没有目录层），
这时候最后一段同时是文件名，直接当文件名用也没问题 —— 但要保证合辑还是归到一起，
所以拼成了 `合辑/{album}/artist - title.ext`。三种模板形状（有目录 / 无目录 / 文件名里带歌手）
都写了测试。

**3. 类型上 `trackArtists` 到底该不该必填，来回改了两次。**

`isCompilation` 只看专辑级字段，但 `albumArtistsFor` 需要曲目歌手做回退。
第一版把 `trackArtists` 设成必填，导致所有只判合辑的调用点（`download.ts`、两个测试）
都得凭空传一个用不上的数组。改成可选后 `namesOf` 又漏了 `undefined` 分支，
`value === null` 判不出 `undefined`，`list` 可能是 undefined。→ 改成 `value == null`。

**4. `npm run check` 里的 build 相关测试在本次改动前就是红的。**

`tests/entry.test.ts` 的 5 个用例（普通路径 / 改名产物 / 路径带空格 / 路径带中文 / import 不执行 main）
全部报 `ERR_UNSUPPORTED_ESM_URL_SCHEME ... Received protocol 'c:'`。
`git stash` 后跑干净工作树，同样红（而且更多，14 个），属于另一批未完成的 Steam / 代理改动。
→ 没有顺手修，避免把两件事混进一个提交。

## 实测

`388647552` / `166043538` 两张专辑走完整链路（真实接口，只算路径不下载）：

```
雪中莲: album.artists=["群星"] 曲目.ar=["王菲"] 合辑=true
  标签 album_artist=["Various Artists"]
  落盘 合辑/那些年的华语情歌/01 雪中莲.flac
Idol: album.artists=["YOASOBI"] 曲目.ar=["YOASOBI"] 合辑=false
  标签 album_artist=["YOASOBI"]
  落盘 YOASOBI/Idol/01 Idol.flac
```

测试变红的验证（撤掉修复，确认测试真的会红）：

- 把 `isCompilation` 的群星匹配改成恒 `false` → 3 个用例红
- 把回退逻辑从 `firstOf` 改成 `join(', ')` → `专辑查不到时取第一位` 红

## 没做

这次只影响新下载。要回填得另做 `music retag` 命令，涉及同名冲突、文件被手工改过等一堆边界，
按用户决定先不做。
