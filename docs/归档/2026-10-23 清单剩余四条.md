## 1b：我上一轮改错了方向

0.12.11 我遇到的问题是"`--json` 传了没效果"。当时查到的根因是对的：

```ts
// main.ts
const args = argv.filter((a) => a !== '--pretty' && a !== '--json')
```

入口在路由之前无条件把 `--json` 剥掉了。**但我的处理是把选项改名成
`--with-text`** —— 这能绕过问题，却没解决它：`--json` 这个选项名对
**任何命令**都不可用，下一个想用它的命令还会踩。

这轮改成从入口解决：

```ts
export function restoreCommandFlags(rawArgv: string[], command: Command, rest: string[]): string[] {
  const userPassed = rawArgv.includes('--json')
  const commandDeclares = Boolean(command.options?.json)
  return userPassed && commandDeclares ? [...rest, '--json'] : rest
}
```

- 用户传了 + 命令声明了 → 补回去，命令收到
- 用户没传 → 不凭空加
- 命令没声明 → 保持全局 no-op 的语义（剥掉）

顺带把返回键名对齐清单契约：`data.lrc` / `data.word`
（我原来写的是 `data.lyrics.line` / `data.lyrics.word`）。

**教训：能绕过去不等于修好了。** 改个名字让症状消失，代价是把根因留给了下一个人。

## 1c：`--duration 301` 仍然报歧义

清单的验收值是 `--duration 301`，而两个候选是 302s 和 299s ——
各差约 1 秒，不满足我设的"明显领先 ≥1s"阈值。

清单给了两个选项：按时长排序取最近，**或**返回 candidates 让调用方选。
我选后者（不替用户选版本，同时让程序能选）：

```json
"details": {
  "candidates": [
    { "ref": "wy:3452040831", "title": "Cry For Me", "artists": ["Echo艾歌"],
      "durationMs": 301802, "durationDeltaMs": 802 },
    { "ref": "wy:3410714722", ..., "durationDeltaMs": 1794 }
  ]
}
```

排好序（时长差小的在前），调用方直接取第一个重试即可。

用专门的 `AmbiguousLyricError` 携带结构化数据，而不是往错误文案里塞 JSON ——
那样等于逼着调用方去正则解析。
