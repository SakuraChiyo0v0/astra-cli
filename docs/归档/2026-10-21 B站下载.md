## 加了什么

- 视频下载：BV / av / 链接 / 短链，多分 P 选择，`--audio-only` 只取音频
- DASH 音视频分流下载 + ffmpeg 合并 + ffprobe 核验
- 扫码登录（未登录画质封顶 360P）
- 视频信息、实际可得画质探测、字幕转 srt、自检

## 踩过的坑

**以为未登录也能拿高画质，实测封顶 360P。**
`x/player/playurl` 无论 qn 传 80 / 116 / 120，`data.quality` 都只回 16。
wbi 签名本身也不提升画质（签名前后都是 16）—— 签名只解决"接口要不要拒你"，画质取决于登录态和账号权限。

**以为 DASH 是"一个 mp4 链接"，实测画面和声音分成两个流。**
`fnval=4048` 返回 `dash.video[]` 和 `dash.audio[]`，必须分别下载再用 ffmpeg `-c copy` 合并。
不合并的话产物只有画面没声音。这也决定了 B 站能力**必须有 ffmpeg**，和音乐那边"纯 TS 写标签、不依赖 ffmpeg"的选择不同。

**同一画质有多种编码，不能拿第一个。**
`dash.video` 里同 id 会并列 avc1 / hev1 / av01。默认取第一个可能拿到 AV1，
老播放器（包括一些 NAS 上的播放器）解不了。改成优先 avc1 → hevc → av01。

**以为多分 P 就该全下，实测这是危险的默认值。**
番剧动辄几百 P，一口气全下既费流量又占空间，而且用户往往只要其中一集。
改成"多 P 时只下第 1 个并明确提示"，要别的用 `--page`。

**入口文件判断写死了文件名，产物改名后静默不执行。**
`main.ts` 原来只认 `main.ts / astra.mjs / astra`。我把产物复制成 `astra-bili.mjs` 做并行测试，
程序退出码 0 但一个字节都不输出 —— 排查了好一会儿才想到是入口判断。
改成"文件名以 astra 开头 + 常见扩展名，或就是 main.ts"。

**路径模板里空变量会留下脏字符。**
`{page:02} {part}.{ext}` 在 part 为空时产出 `01 .mp4`（模板里的字面空格留下来了）。
这个 bug 在音乐那边也存在（曲目号为空时），顺手把模板抽到 `core/template.ts` 一起修了。

**b23.tv 短链要展开后再解析。** 解析器先按文本匹配，不中才去联网展开，避免每次解析都发请求。
