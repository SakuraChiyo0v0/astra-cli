# 2026-10-21 VRChat 能力迁移

从 astrahub 迁移 VRChat 到 astra-cli。astrahub 那边是 3158 行、63 个操作、15 个模块。

## 做了什么

按 astra-cli 的域结构重写，不是照搬：

```
src/vr/api.ts       传输层（固定官方源、强制 UA、错误归一）
src/vr/auth.ts      账号密码登录 + 两步验证 + 会话
src/vr/data.ts      只读：好友 / 世界 / 实例 / 通知 / 收藏 / 群组 / 头像 / 余额
src/vr/actions.ts   写操作：加删好友、收藏、邀请、改状态、通知已读
src/vr/commands.ts  命令层
src/core/confirm.ts 通用的写操作二次确认（音乐域红心也改用它）
```

19 个命令。只读命令直接返回；写命令统一"预览 → 令牌 → 确认"。

## 踩过的坑

**以为 `/health` 是免认证的探活端点，实测返回 401。**
`GET /api/1/health` 带 UA 时返回 401 `{"error":{"status_code":401}}`。换成 `/config`：
免认证可用，但返回几十 KB（整个客户端配置）。所以探活时只读 `availableLanguageCodes` 判断可达，
不把整份配置带进对话。

**不带 User-Agent 会被 Cloudflare 拦成 403，而不是 401。**
实测：`curl` 不带 UA → 403；带上 UA → 401（需要认证）。403 看起来像"没权限"，
实际是"没告诉服务器你是谁"。这条沿用自 astrahub 的记录，这次亲自验证了。

**登录是 GET 不是 POST，而且要 Basic 认证。**
`GET /auth/user` + `Authorization: Basic base64(urlencode(user):urlencode(pass))`。
密码里有 `@`、`:` 时不做 URL 编码会 401 —— 这条要求很反直觉。

**两步验证的会话要用第一步的 cookie。**
开启 2FA 时第一步只返回中间会话，`requiresTwoFactorAuth` 告诉你可用方式。
`POST /auth/twofactorauth/<方式>/verify` 成功后**不会**下发新会话 cookie，
verify 的响应只是票据；真正能用的还是第一步那个 `auth=<uuid>`。

**写操作的确认机制值得抽出来。**
音乐域的红心写过一套"预览 + 一次性令牌"，VRChat 有 7 个写操作，再复制一遍就是重复代码。
抽成 `core/confirm.ts`：按用途分文件存待办（`pending-<purpose>.json`），
令牌绑定"动作 + 参数指纹"，参数顺序不影响指纹。

## 范围说明

astrahub 的 63 个操作里，这次搬了 19 个命令覆盖的核心部分。没搬的：

- 经济交易明细（`vrchat.economy.transactions`）：只做了余额
- 群组的加入/退出/公告/权限（写操作，且用得少）
- 头像的创建/选择/搜索：只做了"我的头像"和"当前头像"
- 收藏分组的创建/删除
- 权限与系统统计类

这些都是"平时用不上"，真要用了再按同样的结构补。

## 补记：分组、头像、系统（同日）

补了三块。

**收藏分组**：`POST /favorite/groups` 建、`DELETE /favorite/groups/{name}` 删。
建之前先查同名分组（省得建出两个重名的），删之前把分组里的收藏数报出来 —— 删分组会连带删掉那些收藏。

**头像**：`PUT /avatars/{id}/select` 切当前、`PUT /avatars/{id}/selectFallback` 设回退。
切换前先去"我的头像"列表核对这个 id 是不是自己的，不是的话在预览里明确标出来 —— 上游会拒，
但提前说清楚比让用户等一个失败好。

**系统与权限**实测：
- `/visits` 免认证，直接返回一个数字（当时是 50378）
- `/time` 免认证，**这次返回标准 ISO 格式** `2026-10-21T10:23:31+00:00`；
  astrahub 在 2026-09-23 记录的是 `09/23/2026 20:35:32` —— 上游改过格式。
  所以这里只原样返回字符串，不解析、不换算时区
- `/permissions` **需要登录**，返回的是"VRChat 定义了哪些权限"，不是"我这个账号有哪些权限"。
  命令说明里写清楚了，免得 AI 把它当成后者转述

至此 VRChat 域 27 个命令。价格、经济交易明细、群组的加入退出与权限管理仍未搬。

## 补记二：经济类（同日）

补了余额、交易明细、收藏上限。

**余额端点原来用错了。** 我第一版写的是 `/user/subscription`（想当然），
astrahub 用的是 `GET /user/{id}/balance`。后者需要先拿到自己的 id 再拼路径。
两处都做完了才发现，已改。教训：同一平台的接口别凭印象写，先看参考实现。

**余额缺失是 null 不是 0。** 0 表示"余额真的是零"，null 表示"上游没给这个字段"。
两者含义不同，混起来会把"没数据"说成"你没钱"。

**交易明细的 status 有新值时原样转述。** 已知 active / failed / succeeded / cancelled，
但上游随时可能加。所以不写死枚举、不把未知值解释成成功或失败，原样带出去。
原始响应也整体保留在 `raw` 里，字段随版本变化时不用改代码。

**收藏上限三类分开给。** `/auth/user/favoritelimits` 返回 avatar / friend / world 三个数，
不合并成一个总数 —— 合并了就看不出是哪类满了。

## 补记三：统一任务视图（P0-2）

加了 `astra jobs` / `astra job <id>`，不用记域名就能看所有域的任务。

**发现一个隐藏的真 bug**：`jobs.quality` 列是 `NOT NULL`，但没有"档位"概念的任务
（VRChat 类）建不出来 —— 测试里 `profile` 不传就报 `NOT NULL constraint failed`。
这解释了为什么之前一直没暴露：音乐传音质、B站传画质，两条路都恰好有值。

**差点做错的地方**：我一开始以为要重建表、把 `domain` 加成独立列。
查真实数据库才发现 `jobs` 表根本没有 `domain` 列 —— domain 是存在 `meta` JSON 里的
（`{"domain":"bili"}`），由 `toView` 读出来、缺省当 music。按那个思路写迁移会直接失败。

**SQLite 改约束只能重建表**，所以迁移是「建新表 → 拷数据 → 删旧表 → 改名」。
真实数据库（15 条记录、4 个任务、23 个任务项）先复制副本验证、再正式执行：
版本 17→22，数据一条不少，`quality` 已可空，无档位的任务能插入。
正式执行前留了 `astra.db.pre-migrate` 备份。
