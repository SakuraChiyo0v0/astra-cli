# 2026-10-23 `music lyric` 命令

Hermes 需求清单第五版的 P2#11。它在库里攒了 205 首 B 站翻唱 mp3
（`bili get --audio-only` 下的），想补歌词，但**不能重下** —— 重复占盘，
还会打乱已经整理好的文件名和标签。astra 内部本来就有两条歌词链路，
但只在下完一首歌时顺带用，没有对外的命令，于是它用 Python 复刻了一份。

## 做了什么

```
astra music lyric <关键词|ref> [--word] [--out <路径>] [--duration <秒>] [--json]
```

两条链路各管一段：

| 环节 | 来源 | 作用 |
|-|-|-|
| 匹配 | 网易云搜索 | 确定"是哪首歌"，拿它的时长 |
| 逐行 | 网易云 `lyric()` | `[mm:ss.xx]文本`，含翻译合并 |
| 逐字 | 酷狗 KRC | `<mm:ss.xx>` 逐字时间戳，自带三道时长闸门 |

`--duration` 覆盖校验基准：库里是 B 站音频时，网易云记录的时长不是这首歌的，
逐字的三道闸门（搜索候选 ±3s、KRC 候选 ±3s、`[total:]` ±5s）全都会对不上。

## 踩过的坑

### 1. 搜「年轮」第一条不是张碧晨

我的第一版 `pickLyricTrack` 在没有基准时长时只看歌名，取排序第一条。跑验收时
匹配到 **汪苏泷 245s**，而清单期望的是张碧晨 274s。

实测网易云搜索前几条：

```
1. 年轮 - 汪苏泷      4:06  (246s)  "男声版插曲"
2. 年轮 - 张碧晨      4:35  (275s)  "插曲"        ← 这才是原版
3. 年轮 (DJ版) - DJ小楷  4:38
4. 年轮 - 张碧晨/周芷莹  1:53  (113s) 对唱现场版
```

**只按歌名取第一条就会拿错版本**，而不同版本的歌词和时长都不同。
这正是 AGENTS.md 第 4 条「拿不准就返回候选，不替用户选版本」的场景。

改成：
- 歌名并列时报 `LYRIC_AMBIGUOUS`，把候选列出来（带 `wy:<id>` 和时长）
- 带歌手时才继续，且歌手匹配要**精确**：查询里点到几个歌手就要对上几个，
  `年轮 张碧晨` 对 `张碧晨/周芷莹` 只能算部分匹配（0.8），否则歧义永远消不掉

第一版歌手匹配用的是"子串包含"，结果 `年轮张碧晨` 和 `年轮张碧晨周芷莹`
都包含查询串、都拿 1.0，还是报歧义。改成拆开逐个数才行。

### 2. `[total:0]` 被当成真实时长

修完版本选择后，逐字仍然拿不到。日志：

```
{"event":"lyric.rejected","id":"32897777","reason":"krc-total","totalMs":0,"wantMs":245822}
```

酷狗有一部分 KRC 的头部就是 `[total:0]`。原代码的判据是
`totalMs !== null && |totalMs - duration| > 5000`，把 0 当成"时长是 0 秒"，
与任何歌都差出几分钟，于是把**正确**的逐字歌词整批丢掉。

`kugou-lyric.ts` 的注释本来就写着"读不到 total 说明信息缺失，不构成错位证据"，
但 `[total:0]` 是"读到了、但值是 0"，绕过了这个意图。加 `totalMs > 0` 才算数。

### 3. 制作人员行会被当成第一句歌词

KRC 带出了「词：汪苏泷」「曲：汪苏泷」「编曲：汪苏泷」三行，
时间戳挤在开头 4~18 秒。播放器会把它们当成歌词高亮 —— 用户看到的是
"作词: 汪苏泷"在闪。加了 `isCreditLine()` 过滤，逐字从 61 行降到 58 行
（清单的实测基准是过滤后 57 行）。

## 验证

清单给的验收基准，逐条对上：

```bash
astra music lyric "年轮 张碧晨" --word --out /tmp/y.lrc
# ✅ 匹配 年轮 - 张碧晨，274504ms（清单说 274s）
# ✅ /tmp/y.lrc 含 <00:18.81>圆<00:19.15>圈<00:19.57>勾<00:19.97>勒<00:20.34>成<00:20.71>指<00:21.16>纹
# ✅ 首行正文 [00:18.81] 圆圈勾勒成指纹（清单基准 [00:18.82]）
# ✅ 逐字 58 行（清单基准 57 行）
# ✅ /tmp/y.line.lrc 是逐行格式，不含 <00:

astra music lyric "不存在的歌名xxxx"
# ✅ LYRIC_NO_MATCH，不静默返回别的东西

astra music lyric "年轮"
# ✅ LYRIC_AMBIGUOUS，列出 10 个版本让用户选
```

`--duration` 也验了：`--duration 100` 时三道闸门全部拒绝逐字，逐行照常返回。

两条防线都做过"撤掉修复确认变红"：
- `pickUnique` 退回"取第一条" → 歧义测试红
- 关掉 `isCreditLine` → 制作人员行测试红

## 没做的

- 翻译歌词在逐字版本里没有合并（逐行版有）。酷狗 KRC 不带翻译，网易云的翻译
  只能按行时间戳对齐，逐字粒度对不上，硬合会错位
- 207 首批量补词没跑（那是 Hermes 自己的活）。单首验了多种情形，判据有单测兜着
