# 2026-10-23 `music covers` 漏覆盖检测 + 两处静默漏封面

用户提了两件：一是清单新增 P2#12（B 站音频写发行年份），二是顺手指出
`music covers` 应该有"有内嵌封面却没写出 cover.jpg"的兜底检测。

## 1. P2#12 发行年份：其实早就写了

`audio-tag.ts` 里 `date: info.pubdate ? new Date(info.pubdate * 1000)...` 一直存在，
`music/tags.ts` 也一直写 `TDRC`（ID3）/ `DATE`（Vorbis）。实测确认：

```
$ astra bili get BV19K421a7kx --audio-only
ffprobe → "date": "2024-03-29"     ← 和清单期望值一字不差
FLAC 同理 → "DATE": "2024-03-29"
```

清单写"**但没有日期**"是它没注意到（这个字段在做 BV 号标签那轮就一起带了）。

**唯一真实的缺口**是：视频没有 `pubdate` 时（`api.ts:91` 兜底成 `0`）
会**静默不写日期**。用户看到播放器里年份永远空白，却没有任何提示。
补了一句 warning。不改成"写今天"—— 那正是清单明确要避免的"抓取时间"。

## 2. `music covers`：两处会静默漏掉封面

### 2a. 一个目录只试第一首

```ts
for (const [index, track] of tracks.entries()) {
  const albumDir = path.dirname(track.path)
  if (seen.has(albumDir)) continue     // 这目录处理过了，后面的歌全跳
  ...
  const cover = extractCoverArt(buffer)
  if (!cover) result.failed.push({ ..., reason: '文件里没有内嵌封面' })
```

同一目录里有多首歌时，只有**排在第一的那首**会被尝试。它恰好没有内嵌封面
（纯音乐、翻唱、或下载时平台就没给图）就会报"这个目录没封面"，
而第二首其实有 —— 封面本该写得出来。

改成按目录分组后挨个试，直到抠出封面为止。

### 2b. 同一专辑散在多个目录

合作曲按主歌手归目录（P0#1 的改动）之后，一张专辑可能同时存在于
`歌手A/专辑/` 和 `歌手B/专辑/`。原逻辑用"目录完整路径"做 `seen`，
这个是对的；但一旦有人图省事把它改成按专辑名去重，第二个目录就永远拿不到 cover.jpg。

补了一条测试钉住：同名专辑在不同歌手目录下，**每个目录都要有自己的 cover.jpg**。

### 2c. `missing` 才是脚本该用的判据

原有 `failed` 是"这一张为什么没写成"，混着两类完全不同的情况：

- 文件里就没有内嵌封面 → 数据问题，补不了，要靠联网或手工
- 有内嵌封面但没写出来 → **bug**

用户要的是后者能被看见。新增 `missing`：**跑完之后仍然没有 cover.jpg 的目录**
（两种情况都收，带 reason）。命令的 warnings 再按 reason 分成两句，
把"有封面却没写出来"单独点出来。

## 踩的坑：测试没复现到目标场景

第一版测试 A 是这么写的：

```ts
register(makeFlac(dir, '01.flac', false), 'a1')   // 没封面
register(makeFlac(dir, '02.flac', true), 'a2')    // 有封面
```

然后把实现退回 `dirTracks.slice(0, 1)` 验证测试会红 —— **结果照样绿**。

原因：`allTracks()` 是 `select * from tracks order by created_at desc`，
**后注册的排在前面**。所以实际处理顺序是 `02.flac`（有封面）在前，
`slice(0,1)` 正好拿到有封面的那首，误报场景根本没复现。

调换注册顺序（先注册有封面的、再注册没封面的）之后才真正变红。
**这次教训不是"要写测试"，而是"要确认测试真的站在 bug 的路径上"** ——
和之前 `durl` 那次（测了 `processBiliAudio` 而不是"要不要调它"）
是同一类问题。
