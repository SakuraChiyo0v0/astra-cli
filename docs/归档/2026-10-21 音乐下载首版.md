# 2026-10-21 音乐下载首版

## 定了什么

- CLI 独立实现，不调用 NAS 上的 music-web / astrahub。music-web 的 `lx-host.ts`、`audio-probe.ts`、`path-template.ts` 只参考思路，代码重写
- TS + Node 24，开发直接跑 `.ts`，发布用 esbuild 打成单文件；运行时依赖为零（`node:sqlite`、`node:vm`、`fetch` 都是内置）
- 写标签用纯 TS（ID3v2.4 / FLAC 元数据块），不依赖 ffmpeg；音频字节写前写后比哈希
- 搜索、元数据、歌词、封面走网易云官方接口；音源只负责取直链

## 踩过的坑

**以为网易云 + qdy 就能下无损，实测网易云路线几乎只有 128k。**
qdy v9.3 对网易云请求 flac / 24bit，`アイドル`、`群青`、`光年之外` 等 8 首样本全是 128k MP3（按 字节数÷时长 算）。
原因是 qdy 里真正能出链的只剩"溯音163"（oiapi.net），它不收音质参数；星海主 API 返回 400，Huibq / 聆川是占位地址。
→ 加了酷我同曲路线：酷我经 qdy 请求 flac 能拿到真 FLAC（周杰伦《床边故事》整张 24bit/48k）。

**以为 qdy 返回了 URL 就是能下，实测有的是 404 的 php 页面。**
"长青 SVIP" 只拼模板 `http://…/wy.php?id=…&level=…`，不请求就直接返回；qdy 的 `validateUrl` 只校验 `^https?://`。
周杰伦的歌在网易云路线上 qdy 全部回落到这个模板。→ 宿主拿到地址必须先 Range 探测，HTML / 4xx 都算失败。

**以为"高档位和低档位返回同一个地址"就能提前放弃，结果把 404 的地址也记进去了。**
第一版把所有返回过的地址都记进去重集合，php 网关的 query 带 level 参数却被截掉比较，flac 404 之后 320k / 128k 被判"同一个文件"直接跳过。
→ 只把探测通过的地址记进去重；php 网关连 query 一起比。

**以为搜"晴天 周杰伦"第一条就是原唱，实测原唱已不在网易云。**
前 15 条全是深情版 / 钢琴版 / 女声版 / "晴天 (原唱 周杰伦)"。所以版本判断不能"取第一条"：
歌名命中 + 歌手命中 + 没有版本标记 + 明显领先才直接下，其余一律返回候选让用户选。用真实搜索结果做测试夹具。

**以为同名同歌手的多个结果是"有歧义"，其实是同一首歌被收进了多张精选。**
"海阔天空 Beyond" 前排是两张华纳精选。→ 同名同歌手视为同一首，优先非精选、发行最早的原专辑（《乐与怒》），其余作为 `otherVersions` 返回。

**歌单 `/api/v6/playlist/detail` 的 `tracks` 不全。**
35 首的歌单只给 10 条 `tracks`，`trackIds` 才是全量。→ 先取 trackIds 再批量查详情。

**`pragma busy_timeout` 写在 `journal_mode = wal` 后面不起作用。**
后台 worker 持锁时，前台 `job resume` 打开库在切 WAL 那一步就报 `database is locked`。→ 用 `new DatabaseSync(file, { timeout })` 在打开时设超时，事务用 `begin immediate`。

**vm 里来的数组跟宿主数组 `deepStrictEqual` 不相等。**
音源 `inited` 上报的对象属于脚本的 realm。→ 宿主收到后 JSON 往返拷一份。

**酷我的 FLAC 末尾有一帧解不开（`invalid sync code`）。**
直接从源站下的原始文件也一样，和写标签无关，能解出的样本数与时长一致。不当作失败，未处理。

## NAS 实测（0.1.1）

在 NAS 上用 `node:24-alpine` 一次性容器跑打包产物（Node 24.22 / x86_64），独立的 home 与 music 目录，不碰真实曲库。

**以为酷我按"歌名 + 歌手 + 搜索结果里的时长"匹配就够了，实测直链指向了另一首歌。**
アイドル 在酷我的搜索结果 DURATION=213，和网易云一致；但 qdy 给的 FLAC 自带标签是 `TITLE=夜に駆ける`，时长 261 秒。
第一轮本机测试其实已经把它存成了 `YOASOBI/アイドル/01 アイドル.flac`（我们写的标签盖掉了原来的），当时只看了"拿到 24bit"没核时长。
→ 拿到文件头后再核两件事：文件自带标题（FLAC Vorbis Comment / ID3 TIT2）与网易云歌名、别名、译名都对不上 → 拒绝整条路线；
FLAC 头部算出的时长差 > 10 秒 → 同样拒绝。拒绝后回落到网易云路线的 128k，并如实标 `downgraded`。
同一个专辑的其它 9 首时长都与网易云一致（差 ≤ 1 秒），只有这一首出事。

**歌单任务里，成功项的"音质降级"提醒存在 error 列里，`job --items` 看起来像失败。**
→ 对外拆成 `error`（只在 failed 时有）和 `note`；`job` 结果里加音质分布（"24bit 9 / flac 1"），任务结束的飞书推送也带上。

**`astra ... | head` 读端提前关闭时 Node 直接抛 EPIPE 堆栈。** → stdout 遇 EPIPE 安静退出。

热歌榜前 8 首的实际音质：flac 1、320k 1、128k 6。对热门新歌，qdy 两条路线大多只有 128k。

## Hermes 部署后的权限调整（同日晚）

用户逐步放开权限，按顺序记录下来，便于以后回退：

1. 飞书接好、中文（`display.language: zh`）、模型换 `cn:glm-5.3-flash` + `model.reasoning_effort: low`
2. 删掉 57 个用不上的内置技能（`hermes skills opt-out --remove`），只剩 `astra-music` / `nas-music-library` / `feishu-openapi` / `hermes-agent`。
   会写 `.no-bundled-skills` 标记，重启和 `hermes update` 不再重新灌入
3. 挂 `docker.sock`（含 `group_add: 121`，sock 属组）—— 等价宿主机 root
4. 挂 `/home`、`/volume1` 到 `/host-root/`，先只读，用户要求后改成读写
5. 审批模式 `smart → manual → smart → manual`，最终 `manual`

**踩坑**

- `HERMES_DASHBOARD=1` 写在 `data/.env` 里没用：镜像的 s6 run 脚本只读容器进程环境。必须在 compose 的 `environment` 里传
- `reasoning_effort` 属于 `model:` 段；写到 `agent:` 段不会生效，`hermes config get` 会提示"不是已知键"
- Kura 的服务清单里只写 `backend` 不够，它要从 docker 查 `container_port`/`host_port` 才算得出映射端口；
  hermes 会发绝对路径跳转，那条还要加 `rewriteRedirect: true`
- WebDAV 上传的文件是 000 权限，挂进容器后 hermes 用户读不到，要在 NAS 上 `chmod`/`chown`
- `docker exec ... bash -lc` 会加载登录 profile，把容器 PATH 换成宿主机的，测容器内命令要用 `sh -c`
