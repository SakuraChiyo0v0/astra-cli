# 2026-10-23 `music lyric` 三处实测反馈

Hermes 在 v0.12.10 上试跑 `music lyric`，报了三个问题。三条都能复现，其中一条是我自己的失误。

## 1. 制作信息行 / 歌名行没滤干净

```
逐字 .lrc 首行: [00:00.00]年轮 - 张碧晨 (Diamond)      ← 歌名行
逐行 .line.lrc: [00:00.000] 作词 : 汪苏泷 / 作曲 / 编曲  ← 制作信息
```

播放器把这几种都当歌词滚出来。

### 为什么之前滤了还漏

我上一轮写了 `isCreditLine()` 并接在 `parseKrc()` 里 —— 只覆盖了**酷狗 KRC 那一路**。
`music lyric` 的逐行来自**网易云 LRC**，走的是另一条代码路径，完全没滤。
一个只在单侧生效的过滤器，看起来像做过了，实际只做了一半。

歌名行则是两边都有：KRC 会把 `年轮 - 张碧晨 (Diamond)` 当第一句，网易云 LRC 也会。

### 逐字那版还有个额外的坑

逐字行长这样：

```
[00:00.00]<00:00.00>年<00:00.39>轮<00:00.78> <00:01.17>-<00:01.56> <00:01.95>张<00:02.34>碧<00:02.73>晨<00:03.12> <00:03.51>(<00:03.91>Diamond<00:04.30>)
```

直接对整行做正规化，`<00:00.00>` 这些标签里的数字全混进正文，
判断"这行是不是歌名行"什么判据都不准。**必须先剥 `<mm:ss.xx>` 再判断**。

### 判据

剥掉 title 和 artists 之后，看**还剩多少实质内容**：

- ≤4 字 → 歌名行残留（`年轮 - 张碧晨`）
- 不含中日韩文字且 ≤12 字符 → 英文版名（`年轮 - 张碧晨 (Diamond)` 的 `diamond`）
- 否则是歌词

用"剩多少"而不是"整行多长"：附注长短不影响判断，只有混进真正的歌词才会超。
反向也要保证 —— `年轮转了一圈又一圈` 剥掉"年轮"还剩一整句中文，
不能被当成歌名行删掉。补了专门的测试钉这一条。

## 2. `--json` 从来没生效过（我的失误）

帮助里写着"把歌词正文也放进 data"，实测只有 `matched/hasWord/lines/written`。

**根因**：`--json` 是**全局标志**。`main.ts:359` 在路由之前做了：

```ts
const pretty = argv.includes('--pretty')
const args = argv.filter((a) => a !== '--pretty' && a !== '--json')
```

所以命令永远收不到 `--json`。而它作为全局标志**其实什么也不做** ——
只是被静默吞掉（`--pretty` 才有实际作用）。

调试时绕了个弯：直接调命令对象的 `run()` 时 `--json` 是生效的，
只有走 CLI 不生效。第一反应是 dist 过期，检查后发现 dist 是新的、代码也在，
才想到去读 `main.ts` 的入口逻辑。

改名为 `--with-text`。**没有动全局的 `--json`** —— 那是既有行为，
改它会影响别的脚本。

## 3. `--duration` 在歧义时该能决胜

```
「Cry For Me」有 2 个版本：Echo艾歌（302s）；DJ阿哲（299s）
```

两个候选都在 ±3 秒容差内，所以还是 ambiguous。用户传了 `--duration 302`
就说明他知道自己那版是哪个，此时按"时长最接近"决胜是合理的。

**但不能无条件选最近的**：如果两个候选一样近，时长不构成任何证据，
替用户选就是瞎猜。所以加了"明显领先"的要求 —— 第二名至少差 1 秒。

实测两条边界：
- `--duration 302`（候选 301.8s / 299.3s，差 0.2s vs 2.7s）→ 选中 Echo艾歌 ✅
- `--duration 300.5`（候选差 1.3s vs 1.5s）→ 仍报歧义 ✅

## 一个反思

第一条是"过滤器只做了一半"的典型：`isCreditLine()` 有、测试也有、
归档里还写了"已过滤"，但它只接在两条歌词路径中的一条上。
**同一个能力有 N 条路径时，要逐条确认每个路径都接上了** ——
这和 `music retag` 那次"测试只验结果不验防线"、`durl` 那次
"processBiliAudio 对了但没被调用"是同一类错误。
