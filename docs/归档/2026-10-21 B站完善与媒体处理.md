# 2026-10-21 B 站完善与媒体处理

## 加了什么

**B 站**
- `bili danmaku`：弹幕下载，默认转 ASS（带颜色、描边、滚动）
- `bili popular`：综合热门
- `bili weekly`：每周必看（`--list` 列期数，`--issue` 指定某一期）

**媒体处理（新域）**
- `media info`：时长、编码、分辨率、码率、采样率、帧率
- `media audio`：抽音轨（源是 aac 且没指定码率时直接 copy）
- `media cut`：裁剪（`--start` / `--end` / `--duration`，默认重编码保证切点精确）
- `media transcode`：改格式 / 分辨率 / 码率
- `media thumbnail`：截一帧当封面

## 踩过的坑

**以为弹幕按时间分桶就完事，实测 1011 条只剩 48 行。**
第一版按 4 秒分桶、每桶取 3 条、全部塞在同一时刻飞出。两条后果：大部分弹幕被丢掉，
保留下来的也挤在一起糊成一片。改成：桶缩到 2 秒、桶内每条**分摊到不同时刻**、
总量上限 1200 条。同一个视频从 48 行变 190 行。

**以为"默认不覆盖"就安全，实测差点把源文件毁掉。**
抽音轨时扩展名推断拿了源文件的容器扩展名（`.mp4`），输出路径回落到源文件本身；
测试脚本又传了 `overwrite: true`，结果原视频被截成了 5 秒。
→ 加了铁律：**输出路径绝不能等于输入**，任何 `--overwrite` 都绕不过。
并且在所有四个操作里都传 input 做这个判断。

**以为转码"同格式改分辨率"不常见，实测是最常见的用法。**
`media transcode video.mp4 --width 480` 的输出默认也是 `.mp4`，于是路径 == 输入，被新加的防护拦住。
→ 同格式时自动加 `.transcoded` 后缀。

**以为裁剪和转码的输出路径逻辑可以共用，实测不能。**
裁剪用 `.cut` 后缀（源和产物是同一段内容的两个版本），转码同格式用 `.transcoded`。
这两个后缀不同是对的，硬统一会让文件名语义变糊。

**B 站弹幕有 XML 和 protobuf 两种格式。**
XML（`/x/v1/dm/list.so`）免登录、好解析，够用；protobuf（`/x/v2/dm/web/seg.so`）要解协议，没碰。

**稍后再看需要登录。** 实测未登录返回 `-101`，所以这轮没做。
