# 2026-11-09 小说域（0.52.0）

把 `/opt/data/scripts/novel_get.sh` + `lnovel2epub`（Python，三份重复实现）收进 astra，
成为新的域：`astra novel`。

## 为什么重写而不是包一层 Python

- 落盘、任务、通知、资产库、订阅在 astra 里都有现成的一套，Python 脚本全都自己做了一遍（且不完整：
  没有 resume、没有资产登记、没有追更）
- 三份实现（仓库版、`scripts/` 两个拼装版）规则已经漂移：仓库版有 `--simplified`，NAS 版没有

## 书源实测

| 站 | 直连 | 经 mihomo | 备注 |
|-|-|-|-|
| www.8novel.com | 403 | 200 | 正文地址由混淆脚本拼出，见 `sources/eightnovel.ts` 顶部 |
| img9.8novel.com | 403 | 403（根路径） | 图片本身带 Referer 能取 |
| www.kanunu8.com | 连不上 | 200 | GBK；没有站内搜索 |
| lnovel.tw | 200 | 200 | 走代理更快（0.8s vs 2.1s） |

## 踩到的坑

1. **8novel 第十四卷是下架提示**：每章正文只有一句「因版權問題，文庫不再提供該小說的閱讀！」，
   状态码 200。第一次实测打出了一本 4 章 76 字的「书」。现在 `takedownNotice` 认出来报错，且不写缓存
   （写了就会被当成「已下好」，站上恢复后也不会再取）
2. **水印不止一种字形**：除了旧脚本认的「⑧ΝОνЕ┕。Сοм」，同一章里还有「８ＮОvヨ└．ｃоm」「⒏NσＶｅ└．Ｃом」。
   旧脚本按固定字表匹配，后两种漏掉了。现在先 NFKC 再查同形字表
3. **段首残缺实体**：8novel 正文里有 `p;「…」`（`&nbsp;` 被截断），旧脚本原样写进 EPUB
4. **代理抖动**：索引任务（1,872 页、并发 3）和抓章同时跑时，mihomo 有几秒连续返回空响应。
   core/http 的重试 1.5 秒内打完扛不住，`novel/fetch.ts` 再加 3 秒 / 8 秒两次慢重试
5. **新建任务被判成「已中断」**（core 的老 bug，见 CHANGELOG）
6. **「活著」搜不到「活着」**：OpenCC 不逐字转「著」（「著作」不能变「着作」），
   所以正文转换不动它，但比较书名时单独归一（`TITLE_FOLD`）

## 没做的

- 网文站（起点、番茄、笔趣阁系）：不在这次范围，书源接口能接，需要时再加
- lnovel 的站内搜索：站点没有可用的搜索接口
- 繁转简的分词：OpenCC 原版有，这里只有词组表 + 逐字，个别一字多义会错

## 繁简数据怎么来的

`src/novel/t2s-data.ts` 由 OpenCC 的 `TSCharacters.txt`（4,105 字）和 `TSPhrases.txt`（216 条）生成：
一个繁体字对应多个简体时取第一个候选；字表编码成两个按码点对应的字符串。
数据基本不变，生成步骤不进构建流程。

## 迁移

- `proxy.include` 加上 `8novel.com,kanunu8.com,lnovel.tw`
- `astra config set novel.dir /host-root/volume1/小说`
- `astra lib root add novel /host-root/volume1/小说`，再 `astra lib adopt --root novel` 收编旧书
- `astra novel index --rebuild` 建努努书坊索引（约 10 分钟）
- Hermes 的 `ebook-library` 技能改为指向 `astra novel`；旧脚本留着不删，等用户确认
