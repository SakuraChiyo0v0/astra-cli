# 2026-10-23 music covers 以目录为准（P2#13）

清单 P2#13。Hermes 实测：

```
astra music covers   → {"written":118,"skipped":0,"failed":[]}
find $ASTRA_MUSIC_DIR -mindepth 2 -maxdepth 2 -type d | wc -l   → 119
find $ASTRA_MUSIC_DIR -name cover.jpg | wc -l                   → 118
```

差 1 张（`YOASOBI/アイドル`），`failed` 却是空的。

## 根因：遍历的是曲库记录，不是磁盘目录

原实现：

```ts
const tracks = allTracks().filter((t) => !t.missing)
for (const track of tracks) {
  const albumDir = path.dirname(track.path)
  ...
}
```

**曲库里没有记录的专辑，根本不在遍历范围里。** 那个目录就成了不存在 ——
不是"处理失败"，是"从来没被处理"。所以 `failed` 是空的：
它连"这张没写成"都不知道。

哪些情况会让曲库里没有记录：

- 手动把专辑放进音乐目录（不用 astra 下载）
- 下载成功但 `saveTrack` 那一步失败（磁盘满、进程被杀）
- 记录被 `astra music forget` 清掉（forget 只删记录不删文件）
- 库是重建过的，老文件没回填

这三种都不算罕见，而任何一种都会让这张专辑的封面永远补不上，
且**没有任何信号**。

## 上一版没修到根上

0.12.12 我修了两处（一目录多首歌挨个试、同名专辑多目录），
`missing` 也加了。但那版仍然遍历 `allTracks()` —— **只解决了"目录里有记录
但没写出来"，没解决"目录里根本没记录"**。

清单第 1 条正好点在这里：「遍历以**目录**为准，不以曲库记录为准」。
Hermes 是在 0.12.12 部署之前测的，而我修的时候也没让它跳出曲库这个前提。

## 改成什么

```ts
const dirs = await findAlbumDirs(root)   // 扫磁盘：装音频的目录都算
```

`findAlbumDirs` 的判据：

- 只认**直接含有音频文件**的目录 —— 歌手那层（只有子目录）不该给它写 cover.jpg
- 容忍 `<歌手>/<专辑>/` 和 `<专辑>/<碟>/` 两种深度
- 音频扩展名按白名单认（flac/mp3/m4a/ogg/opus/wav/aac/wma）

候选音频文件取**曲库记录与磁盘实际文件的并集** —— 曲库有记录就用（省一次
readdir），没有也能从目录里现场找到。

判断"要不要写"也换了：看 `cover.jpg` 在不在，而不是"曲库记录 + 内嵌封面能不能读到"。

## 新增的自检

- `dirs`：扫到多少专辑目录
- `hasCover`：跑完之后**确实有** cover.jpg 的目录数（含原来就有的）
- 恒等式 `dirs == hasCover + missing.length`，有测试钉住
- `--verify`：只自检不写，直接列出缺封面的目录 —— 对应清单第 4 条

## 验证

新增 7 条测试，其中"曲库没收录的专辑也要覆盖"是 #13 的核心场景：
磁盘上有文件、**完全不注册进曲库**，断言仍能写出 cover.jpg。

把实现退回 `[...new Set(allTracks()...)]` 后，**5 条测试同时变红**，
包括核心那条：

```
✖ 曲库没收录的专辑也要覆盖（P2#13 的核心）
✖ 目录里排在前面的那首没封面、后面的有：仍应当写得出来
✖ 整目录都没有内嵌封面：列进 missing 并说明原因
✖ 同一专辑散在两个目录：每个目录都要有自己的 cover.jpg
✖ 已有 cover.jpg 的目录跳过，dirs/hasCover 如实计数
```

`npm run check` 302 项全过。

## 一个反思

0.12.12 那次我按用户说的加了 `missing`，也修了两个具体 bug，
但**没有回到"这段代码的前提是什么"**。"遍历曲库"这个前提从一开始就错了，
而我只在它上面打补丁。用户的清单第 1 条其实写得很清楚（"以目录为准"），
我当时读成了"加个 missing 就行"。

**需求里的第 1 条往往不是建议，是根因。**
