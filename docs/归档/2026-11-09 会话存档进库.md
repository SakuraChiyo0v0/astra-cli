# 2026-11-09 会话存档进库（0.55.0）

## 做了什么

`astra archive sync`：读 Hermes 的 `state.db`，把会话、消息增量写进 astra 正在用的库。
PG 落 `hermes.sessions` / `hermes.messages` / `hermes.documents`，SQLite 用 `hermes_*` 前缀。

之前这件事由 `/opt/data/scripts/archive_sessions.py` 干，落的是另一套库；并进来以后一条命令就能查。

## 踩过的坑 / 决定

- **迁移号撞了**。这套改动最初是在 0.53 之前写的，迁移编号 `0005_hermes_archive`，
  但主线后来把 `0005` 用于「资产归属与可见性」（`astra_0005_asset_visibility`）并已上线。
  合并时顺延成 `astra_0006_hermes_archive`，同时按主线的命名规则加 `astra_` 前缀。
  教训：**迁移 id 是全局单号，写之前先看 MIGRATIONS 数组末尾**。
- **`kind` 列被删掉了**。原设计给会话分 painting / mixed，后来判断没有查询价值，
  改成整段存、不分类。所以这套改动最后只剩建表，没有 0006 那个 drop 迁移。
- **测试里写死了迁移清单**。`tests/db-adapter.test.ts` 断言 `applied` 数组和 `skipped` 条数，
  新增迁移要同步改三处（数组、skipped 数、applied 数），否则报的错是 `6 !== 5`，跟迁移本身没关系。
- **`if not exists` 全部加上**。线上 PG 里 `hermes` schema 已经由外部脚本建过，
  迁移重复执行必须无害，否则第一次 `db migrate` 就会挂在「表已存在」。
- **命令自己先查迁移**。缺表时直接报 `CONFIG` + 「先跑 astra db migrate」，
  而不是写到一半才发现没有表。

## 没做的

- 没有把 `archive_sessions.py` 停掉。两套并存一段时间，确认 astra 这边数据对得上再停。
- Hermes 的 cron 没改；要接的话是在 `archive_sessions.py` 那一条后面再加一行 `astra archive sync`。
