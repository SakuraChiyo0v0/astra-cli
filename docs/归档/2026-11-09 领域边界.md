# 2026-11-09 领域边界（0.53.0）

方案全文在 NAS 的 `docs/astra-lazy-domains-plan.md`。这里记做的过程中踩到的东西。

## 做了什么

- P0：`tests/surface-golden.test.ts` 把 `help` 全量清单、hidden 命令名、`config` 说明、
  全部配置键（含 validate 对一组探针值的接受 / 拒绝结果）序列化成 `tests/fixtures/surface.json`，逐字节比对
- P1：ffmpeg / 写标签下沉 core，lx 并进 music，领域清单 + 登记表，边界测试

## 踩过的坑 / 决定

- **`index.ts` 不能当清单文件名**：`quark/index.ts` 已经存在（导出 `humanSize`，cloud 在用）。改叫 `manifest.ts`
- **help 顺序**：原来 `db` / `lib` 两组命令排在 model 和 quark 之间，登记表要保持这个位置，
  否则金样测试就红（也确实会改变 AI 读到的清单）
- **配置键拆分推迟**：本来要把 46 个配置键按领域拆进各自的清单。查下来跨域读键很多：
  `music.ffmpeg` 被 bili / comic / media / novel 读，`music.template` 被 bili 读，
  `lib root auto` 读 bili / pixiv / comic 的目录键。键要是跟着领域走，懒加载后
  `config set bili.dir` 就得先加载 bili。结论：配置键表留在 core（它只是数据，不 import 领域代码），
  只把 `core/config.ts` 对 `bili/sign.ts` 的那一处 import 留作老账，P2 再处理
- **doctor / sessions 推迟**：两者都要「问每个领域」。拆成注册表的前提是领域按需加载（P2），
  现在拆只是把 import 换个地方。先列进边界测试的白名单，只许减不许加
- **测试要用 hermes 用户跑**：用 root 跑 `npm run check` 时 `doctor.test.ts` 的只读目录用例会失败
  （root 无视权限位），不是代码问题。同理 root 跑过的 git 命令会把 `.git/index` 变成 root 所有
