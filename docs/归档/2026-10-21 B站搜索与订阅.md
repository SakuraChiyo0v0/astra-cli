# 2026-10-21 B 站搜索与订阅

按实际使用反馈补的 P2 两项。

## 加了什么

- `bili search <关键词> [--type video|user]`：视频与 UP 主搜索
- `bili collection <链接|ref>`：只列清单不下载，每项带 `downloadWith`
- `bili subscribe add/list/set/remove/run`：定时盯合集 / 系列 / 收藏夹，出新视频自动下

## 踩过的坑

**以为 UP 主视频列表能带签名拿到，实测 -352。**
`/x/space/wbi/arc/search` 带 wbi 签名、带 UA、带 Referer，一律返回 `-352 风控校验失败`。
搜索接口（`search/type`）反而能过。所以这块只给搜索、不列投稿 —— 和 astra-hub 文档里的结论一致。
没有硬啃，在错误提示里写明了原因。

**订阅表有 `created_at` 非空约束，第一次插入直接失败。**
报错是 `NOT NULL constraint failed: subscriptions.created_at`。
表是音乐域建的，B 站复用时漏了这个字段。教训：复用别人的表要先看清全部约束，
不能只看自己用到的列。

**第一次跑订阅会把整个合集当新视频 —— 这是这个功能最危险的坑。**
`last_seen` 为空时如果直接求差集，"上次没见过"的就是全集，一次下几百个。
所以建订阅时**先把当前内容记为基线**，第一次 run 返回空。
这条单独抽成 `pickFresh()` 并写了测试，撤掉基线保护会红 2 条。

**mid 为空时 targetId 写成了 `season:/1903592`。**
带空斜杠的形状解析虽然容忍（正则里 mid 是可选的），但存进库很难看，
容易让人以为数据坏了。改成 mid 为空就不写斜杠。

**搜索接口的 `duration` 有两种形态。**
有时是 `"12:34"` 字符串，有时是纯秒数。统一用 `parseSearchDuration` 归一。

## 当下的事实（2026-10-21 实测）

- 视频搜索：`YOASOBI` 返回正常，带 bvid / 时长 / 播放量 / 弹幕数 / 分区
- 用户搜索：`老番茄` 返回 mid / 粉丝数 / 投稿数
- 订阅：建订阅记 23 个基线 → 第一次 run 报"没有新视频" → 手动移除一个 bvid 后
  run 报"发现 1 个新视频，已开任务"
- 合集 / 系列 / 收藏夹三种来源都走同一套订阅逻辑

## 没做

- 订阅 UP 主（风控，做不了）
- 订阅后发现新视频时的即时通知（现在只开任务，任务结束有通知）
- 搜索的多页游标（B 站的页码够用，没做游标）
